  ЭТАП 1. ОПИСАНИЕ АРХИТЕКТУРЫ И СИСТЕМЫ КОМАНД (ISA MANUAL)
  Проект: специализированное процессорное ядро (Harvard)
  Дисциплина: Вычислительные средства АСОИУ
1. СТАТУС ВЫПОЛНЕНИЯ ЭТАПА 1
Этап 1 выполнен в проекте.
Формат команды (opcode, регистры, imm)    Да    раздел 3, rtl/top_cpu.v
Регистровый файл (8 x 16 бит)    Да    раздел 4, rtl/reg_file.v
ADD, SUB    Да    раздел 5, rtl/isa_defs.vh
AND, OR, XOR, NOT    Да    раздел 5, rtl/alu.v, control
LOAD, STORE    Да    раздел 5
JUMP, BEQ    Да    раздел 5
  - LDI  — загрузка константы в регистр (удобно для тестовых программ).
Команды XOR и NOT описаны в ISA и реализованы в ALU и блоке управления;
в тестовой программе tb/program.hex они пока не используются, но доступны
для программирования ядра.
2. ОБЩАЯ АРХИТЕКТУРА
Тип: упрощённое процессорное ядро с архитектурой Гарварда.
  - Память команд (instruction memory) и память данных (data memory) разделены.
  - Шина адреса команд (PC) не совпадает с адресным пространством данных.
  - Разрядность слова данных и команды: 16 бит.
  - Счётчик команд PC: 16 бит (адресует до 65536 слов; в проекте ROM 256 слов).
Основные блоки (этап 2, но важны для понимания ISA):
  - program_counter (PC)
  - instruction_memory (ROM + program.hex)
  - register_file (8 регистров)
  - ALU
  - data_memory (RAM)
  - control_unit (декодирование opcode)
3. ФОРМАТ 16-БИТНОЙ КОМАНДЫ
Общая разметка полей (младшие биты справа):
  DR  — регистр назначения (destination), 3 бита → R0..R7
  SR1 — первый источник, 3 бита
  SR2 — второй источник (R-формат), 3 бита
Назначение полей зависит от типа команды (см. раздел 6).
Источник в RTL: rtl/top_cpu.v
  assign opcode = instruction[15:12];
  assign dr     = instruction[11:9];
  assign sr1    = instruction[8:6];
  assign sr2    = instruction[5:3];
4. РЕГИСТРОВЫЙ ФАЙЛ (REGISTER FILE)
Параметры:
  - Количество регистров: 8 (R0, R1, ..., R7)
  - Разрядность каждого регистра: 16 бит
  - Два порта чтения (read_addr1, read_addr2)
  - Один порт записи (write_addr, write_data)
  - Запись: по переднему фронту clk (posedge), при reg_write = 1
  - Чтение: комбинационное (асинхронное относительно адреса)
Особое правило:
  - R0 всегда читается как 0x0000.
  - Запись в R0 запрещена (игнорируется аппаратно).
Источник: rtl/reg_file.v
5. ТАБЛИЦА КОДОВ ОПЕРАЦИЙ (OPCODE)
Коды заданы в rtl/isa_defs.vh.
  Мнемоника   Opcode    Тип     Краткое действие
  ---------   ------    ---     ----------------
  ADD         0001      R       R[DR] <- R[SR1] + R[SR2]
  SUB         0010      R       R[DR] <- R[SR1] - R[SR2]
  AND         0011      R       R[DR] <- R[SR1] & R[SR2]
  OR          0100      R       R[DR] <- R[SR1] | R[SR2]
  LOAD        0101      I       R[DR] <- MEM[R[SR1] + imm6]
  STORE       0110      I       MEM[R[SR1] + imm6] <- R[DR]
  LDI         0111      I       R[DR] <- imm9 (знаковое расширение)
  JUMP        1000      J       PC <- imm12
  BEQ         1001      J       if (z_flag) PC <- imm12
  XOR         1010      R       R[DR] <- R[SR1] ^ R[SR2]
  NOT         1011      R       R[DR] <- ~R[SR1]
  z_flag (zero_flag): флаг «результат последней релевантной операции равен нулю»;
  используется для BEQ.
6. ФОРМАТЫ КОМАНД ПО ТИПАМ
6.1. R-формат (арифметика и логика)
  ADD, SUB, AND, OR, XOR, NOT
  Биты:
    [15:12] = opcode
    [11:9]  = DR
    [8:6]   = SR1
    [5:3]   = SR2 (для NOT не используется как второй операнд; ALU: ~SR1)
    [2:0]   = 000 (резерв, рекомендуется обнулять)
  Пример: ADD R3, R1, R2
    opcode=0001, DR=011, SR1=001, SR2=010 → машинный код зависит от [2:0]
6.2. I-формат (память и константы)
  LOAD, STORE, LDI
  LOAD / STORE — адрес памяти данных:
    effective_addr = R[SR1] + imm6
    imm6 = instruction[5:0], знаковое расширение до 16 бит
  LOAD:  R[DR] <- MEM[effective_addr]
  STORE: MEM[effective_addr] <- R[DR]
         (для STORE в регистровый файл на чтение второго порта подаётся DR)
  LDI — загрузка константы:
    imm9 = instruction[8:0], знаковое расширение
    R[DR] <- imm9
6.3. J-формат (переходы)
  JUMP, BEQ
  Биты:
    [15:12] = opcode
    [11:0]  = imm12 — абсолютный адрес перехода (младшие 12 бит PC)
  JUMP: безусловно PC <- imm12
  BEQ:  если z_flag == 1, то PC <- imm12, иначе PC <- PC + 1
7. СЕМАНТИКА КОМАНД (VERILOG-УРОВЕНЬ)
  ADD:   R[DR] <= R[SR1] + R[SR2]
  SUB:   R[DR] <= R[SR1] - R[SR2]
  AND:   R[DR] <= R[SR1] & R[SR2]
  OR:    R[DR] <= R[SR1] | R[SR2]
  XOR:   R[DR] <= R[SR1] ^ R[SR2]
  NOT:   R[DR] <= ~R[SR1]
  LOAD:  R[DR] <= MEM[R[SR1] + sext(imm6)]
  STORE: MEM[R[SR1] + sext(imm6)] <= R[DR]
  LDI:   R[DR] <= sext(imm9)
  JUMP:  PC <= imm12
  BEQ:   if (z_flag) PC <= imm12
8. ПРИМЕР ТЕСТОВОЙ ПРОГРАММЫ (tb/program.hex)
Файл: tb/program.hex — по одной 16-битной инструкции в строке (hex).
  Адрес  Код     Мнемоника (смысл)
  -----  ----    -----------------
  0      7205    LDI   R1, 5
  1      7403    LDI   R2, 3
  2      1650    ADD   R3, R1, R2      → R3 = 8
  3      6601    STORE R3, [R0 + 1]    → MEM[1] = 8
  4      5801    LOAD  R4, [R0 + 1]    → R4 = 8
  5      2B18    SUB   R5, R4, R3      → R5 = 0
  6      9008    BEQ   8               → переход, если R5==0 (z_flag)
  7      7C01    LDI   R6, 1           → пропускается при успешном BEQ
  8      4E50    OR    R7, R1, R2      → R7 = 7
  9      8009    JUMP  9               → бесконечный цикл (останов)
Проверка программы: симуляция tb_top_cpu (см. SIMULATION_GUIDE.md в корне проекта).
9. СВЯЗЬ С ФАЙЛАМИ ПРОЕКТА
  rtl/isa_defs.vh     — коды opcode и операций ALU (эталон ISA)
  rtl/top_cpu.v       — разбор полей инструкции, datapath
  rtl/control_unit.v  — декодирование opcode → управляющие сигналы
  rtl/alu.v           — выполнение операций ALU
  rtl/reg_file.v      — регистровый файл 8x16
  rtl/instr_mem.v     — память команд, загрузка из tb/program.hex
  rtl/data_mem.v      — память данных
  tb/program.hex      — пример машинной программы
10. ВЫВОД ДЛЯ ОТЧЁТА ПО ЭТАПУ 1
На этапе 1 спроектирована и задокументирована упрощённая ISA для 16-битного
ядра с регистровым файлом 8x16, форматами R/I/J и базовым набором команд,
требуемым заданием. Описание согласовано с реализацией этапа 2 (RTL) и
используется при верификации (этап 3).
Для отчёта можно приложить:
  - этот файл (docs/ETAP1_ISA_MANUAL.txt);
  - таблицу opcode из раздела 5;
  - рисунок формата слова команды из раздела 3;
  - листинг rtl/isa_defs.vh.
